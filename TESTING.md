# Проверка

Установить зависимости разработки: `python -m pip install -e ".[dev]"`.

Запустить `python -m pytest -q` и `python -m ruff check .`.

Тесты покрывают три режима, отсутствие самоназначения и дублей получателей, запреты пар, несовместимые условия, повторную жеребьёвку, изоляцию игр, неизменяемость режима и список владельцев. Дополнительно проверяется игра на 80 человек: 80 разных дарителей, 80 разных получателей, 80 уведомлений, невозможность вступить после жеребьёвки, сложные ограничения пар и их несовместимость. Длинные тексты уведомлений ограничены лимитом Telegram; списки участников и распределение разбиты на страницы по 8 записей.

Также проверяются лимит мест, заявки, замена участника с сохранением взаимно однозначного распределения, черновики, рассылка всем запустившим бота пользователям, медиа и ссылка рассылки, восстановление зависшей отправки.

Миграции проверяются отдельно на пустой базе и на базе со старой структурой, где уже есть пользователи и сообщения. Отдельный тест проверяет отмену отложенных сообщений удалённых функций.

Проверка здоровья контейнера тестируется на доступной базе и свежем/устаревшем сигнале отправщика. Доступ к админскому состоянию и повтор ошибок рассылки проверяются без Telegram API.

Для ручной проверки в Telegram используйте тестового бота и две или более приватные учётные записи: создание игры, вступление, жеребьёвка, доставка назначения, просмотр полного распределения только в разрешённых режимах, страницы списка и возврат назад. Автоматические тесты не обращаются к Telegram API и не доказывают доставку сообщения реальному пользователю.
