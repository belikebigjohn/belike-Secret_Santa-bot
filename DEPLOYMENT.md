# Запуск бота для пользователей

Бот работает с одним процессом long polling. Публичный HTTP-порт не нужен. Для сервера требуются Docker с Compose, постоянный том PostgreSQL и доступ к Telegram API.

## Перед запуском

1. На сервере скопируйте репозиторий и выполните `python scripts/init_env.py`, если `.env` ещё нет.
2. В `.env` задайте настоящий `BOT_TOKEN`, хотя бы один Telegram ID владельца в `OWNER_IDS` и длинный случайный `POSTGRES_PASSWORD` из букв, цифр, `-` и `_`. Не публикуйте `.env`.
3. Убедитесь, что порт PostgreSQL не открыт наружу. В текущем `compose.yaml` у базы нет опубликованного порта.
4. Перед обновлением существующей базы сделайте резервную копию. Миграции Alembic выполняются при старте бота.

## Запуск и проверка

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bot
docker compose exec -T bot python -m santa.healthcheck
```

В `docker compose ps` бот должен стать `healthy` после запуска. Проверка опрашивает базу и контролирует, что фоновой отправщик обновлял сигнал за последние 45 секунд. При сетевой ошибке доставки бот повторяет отправку с задержкой, а после пяти попыток показывает ошибку в админке.

После запуска проверьте в Telegram две учётные записи: `/start`, создание игры, вступление, жеребьёвку и личное назначение. С учётной записи владельца откройте `/admin`, проверьте «Состояние», сделайте тестовую рассылку себе и затем небольшую реальную рассылку. Кнопка отмены и повтор временных ошибок требуют отдельного подтверждения.

## Резервная копия и обновление

На Linux-сервере сохраните дамп до обновления:

```sh
docker compose exec -T db pg_dump -U santa -d santa -Fc > santa-backup.dump
```

Затем обновите код и выполните `docker compose up --build -d`. Сохраните дамп отдельно от сервера. Миграции не удаляют старые игры, но отменяют ожидающие сообщения функций, которые были удалены ранее.

Telegram и PostgreSQL не образуют общей транзакции: при сбое между фактической отправкой и записью результата редкое повторное сообщение возможно. Поэтому перед ручным повтором ошибок проверьте статистику рассылки.
