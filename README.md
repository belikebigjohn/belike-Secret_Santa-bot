# 🎄 Тайный Санта

Telegram-бот для нескольких независимых игр. Ведущий создаёт игру, делится ссылкой, собирает пожелания и запускает жеребьёвку. Участники видят только своего получателя.

## Реализовано

- Три режима ведущего: играет вслепую, играет с полной таблицей, только организует.
- Персональные приглашения со случайным токеном и регистрация.
- Анкета с пожеланиями, редактируемая после жеребьёвки.
- Жеребьёвка с запретами пар, проверкой допустимости и защитой от повторного запуска.
- Личная миссия, отметка готовности подарка, агрегированный прогресс.
- Уведомления о назначениях и действиях игры.
- Разграничение доступа к играм и назначению.
- Правила и обложка игры, управление запретами пар через меню ведущего.
- Анонимные вопросы, ответы, статусы подарка и подтверждение получения.
- Завершение с подтверждением и безвозвратное удаление завершённой игры через кнопку архивации с отдельным подтверждением; передача роли ведущего до жеребьёвки.
- Сводка владельца по команде `/admin` и рассылка всем доступным пользователям бота.
- Черновики, подтверждение заявок, помощники ведущего и замена участника после жеребьёвки.
- Ведущий может исключить участника до жеребьёвки и при необходимости вернуть ему доступ; для длинных списков есть страницы.
- Админские медиа-рассылки с кнопками и тестовой отправкой.

Полный перечень ограничений и план развития — [FEATURES.md](FEATURES.md).

## Запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните токен у себя.
2. В этом локальном проекте `.env` уже подготовлен. После нового клонирования запустите `python scripts/init_env.py`.
3. Откройте `.env` и вставьте токен после `BOT_TOKEN=` одной строкой, без пробелов и кавычек. Остальные строки уже готовы.
4. Установите зависимости: `python -m pip install -e ".[dev]"` и запустите `python -m santa.main`. Это использует локальную SQLite-базу.
5. Для запуска с PostgreSQL установите Docker и выполните `docker compose up --build -d`. Пароль базы в `.env` создаётся скриптом автоматически.
6. Откройте бота в Telegram и отправьте `/start`.

Для локальной разработки нужен Python 3.11–3.15. Конфигурация читается из `.env`; переменные окружения имеют приоритет. Для эксплуатации используйте PostgreSQL через Compose. При запуске Alembic применяет миграции к существующей базе без удаления игр.

Команды разработчика: `python -m pytest`, `python -m ruff check .`.

В боте: `/start` — главное меню, `/help` — помощь, `/admin` — панель владельца. Личных настроек рассылки и напоминаний нет.

Мастер запрашивает три даты по одной в формате `ДД.ММ.ГГГГ`. Время каждой даты — 18:00 по Москве (`Europe/Moscow`); в базе даты сохраняются в UTC. Ранее созданные даты сохраняют свой момент времени в UTC и теперь показываются в московском часовом поясе. Жеребьёвку ведущий запускает вручную после проверки состава игры. Основные кнопки редактируют текущую карточку, а «Назад» возвращает к предыдущему разделу. Кнопки сгруппированы по две, где это удобно; навигация остаётся отдельной строкой.

Имена участников в карточках и уведомлении о жеребьёвке открывают их Telegram-профиль. Обычные иллюстрации после первой загрузки повторно отправляются по Telegram `file_id`, чтобы не загружать PNG с сервера при каждом переходе.

Новые админские рассылки получают все пользователи, которые запускали бота и не заблокировали его. После повторного `/start` ранее заблокировавший бот пользователь снова становится доступен для отправки. Миграция отменяет старые ожидающие объявления и напоминания по играм, а также незавершённые рассылки по удалённым сегментам.

## Развёртывание

Порядок подготовки сервера, запуска, проверки и резервного копирования описан для [Mac mini без Docker](MACOS_DEPLOYMENT.md) и для [Docker Compose](DEPLOYMENT.md). Запускайте один процесс бота с long polling. Для нескольких экземпляров нужен отдельный механизм координации polling.

Прямой доступ к базе и серверу позволяет прочитать назначения. Режим «Играю вслепую» скрывает их через интерфейс бота.
